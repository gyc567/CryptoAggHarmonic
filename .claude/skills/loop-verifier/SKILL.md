# SKILL.md — loop-verifier

## Trigger Condition

- Before any Durable Facts promotion (Episodic → Durable)
- Before any code change generated by a loop is committed
- Called by other loop skills to validate their output

## Input

Reads:
- The proposed change or fact to verify
- `docs/loop-state/MEMORY.md` — memory strategy
- `docs/loop-state/memory-constraints.md` — prohibited content rules
- `docs/loop-state/LOOP.md` — current loop definitions
- Relevant source files for consistency checks

## Output

Returns a verification report with:
- `passed: bool`
- `reasons: list[str]` — why it passed or failed
- `warnings: list[str]` — concerns that don't fail verification

## Verification Rules

### Memory Checks

1. **No prohibited content**: Scan for API keys, passwords, raw LLM outputs
2. **Budget respected**: Entry count and token count within tier limits
3. **No duplicate**: Check existing Durable Facts for contradictions

### Code Change Checks

1. **Test coverage**: New code has tests (`pytest`)
2. **Type safety**: Passes `mypy` and `pyright` on changed files
3. **No regression**: Existing tests still pass
4. **Gate compliance**: Changes don't touch denylisted paths in `gate.yaml`
5. **Backward compatible**: No breaking changes to public APIs

### Consistency Checks

1. **Strategy version**: Verify that `strategy_version` is updated if strategic files changed
2. **Pareto continuity**: If tuning params changed, verify Pareto front moved appropriately

## Verification Levels

| Level | Use Case |
|--------|---------|
| `fast` | Memory hygiene (no tests) |
| `standard` | Most loop verifications |
| `strict` | Durable Facts promotion, major changes |

## Example Usage

```
verifier = LoopVerifier(level="standard")
report = verifier.verify_memory_change(proposed_fact)
if not report.passed:
    abort_promotion(report.reasons)
```
